# Trades Tracker — журнал сделок

Простой журнал трейдера: записывайте сделки и ордера, смотрите P&L и статистику.
Это один файл `index.html` без сборки, сервера и зависимостей.

## Возможности

- **Сделки**: тикер, рынок (крипто, акции, форекс, фьючерсы…), Long/Short, даты входа и выхода, цены, количество, комиссии, стоп-лосс, тейк-профит, сетап и заметки.
- **Расчёты на лету**: P&L, доходность в %, результат в R (от стопа), размер позиции, риск до стопа, соотношение риск/прибыль.
- **Открытые позиции**: оставьте цену выхода пустой. Закрыть позицию можно кнопкой «Закрыть» в таблице: цена выхода вводится вручную или в одно касание по стопу или тейку.
- **Частичные выходы**: в окне «Закрыть» можно указать меньше объёма, и закроется только часть. Когда закрыт весь объём, журнал ставит среднюю цену выхода. Кнопка «Стоп в безубыток» переносит стоп на цену входа, а R по-прежнему считается от начального стопа.
- **Живые цены по крипте**: у открытых позиций с рынком «Крипто» журнал раз в 15 секунд берёт цену с Binance (спот, а если тикера там нет — фьючерсы) и показывает плавающий P&L, расстояние до стопа и тейка. Закрыть позицию можно кнопкой «По рынку». Ключи не нужны, на Binance уходят только названия тикеров.
- **Приложение на телефон**: сайт ставится на экран «Домой» (Safari → Поделиться → «На экран Домой»), открывается без адресной строки и работает без интернета.
- **Статистика**: чистый P&L, винрейт, профит-фактор, матожидание, средняя прибыль и средний убыток, максимальная просадка.
- **Кривая доходности** и результат по тикерам или сетапам.
- **Счёт и риск**: стартовый баланс, риск на сделку в % и дневной лимит убытка. Журнал показывает текущий баланс и его рост, в форме сделки подсказывает объём позиции по стопу, а при приближении к дневному лимиту предупреждает. Настройки синхронизируются вместе со сделками.
- **Ошибки и эмоции**: метки к сделке («По плану», FOMO, ранний выход, передвинутый стоп и свои) и оценка от 1 до 5, насколько сделка шла по плану. В аналитике видно, сколько стоила каждая ошибка и чем сделки по плану отличаются от остальных. Нажатие на метку показывает её сделки.
- **Аналитика**: Long против Short, серии побед и поражений, среднее время в сделке (отдельно у прибыльных и убыточных), P&L по дням недели и по часу входа, распределение результатов в R. Считается по текущим фильтрам.
- **Календарь P&L по дням**: итог каждого дня (по дате закрытия) с цветом по величине результата, итоги недель и месяца. Нажмите на день, и в таблице останутся сделки этого дня.
- **Скриншоты графика** к каждой сделке: кнопка, перетаскивание или вставка из буфера (Ctrl+V). Картинки сжимаются до 1920 px и открываются в просмотрщике.
- **Синхронизация между устройствами** через приватный GitHub Gist (см. ниже).
- **Фильтры и поиск**: статус (открытые, закрытые, прибыльные, убыточные), направление, рынок. Статистика пересчитывается под фильтр.
- **Импорт и экспорт**: JSON (резервная копия) и CSV (для Excel и Google Sheets). Импорт понимает CSV с `,` или `;`.
- **Telegram-бот**: сделки можно записывать сообщением вроде `long BTC 64000 0.1 стоп 63000`, а закрывать сообщением `закрыть BTC 65000`. Сделки попадают в тот же gist и появляются в журнале (см. ниже).
- **Импорт с биржи**: CSV или Excel из Bybit (Closed P&L) и Binance (история сделок или позиций). Из истории исполнений позиции собираются сами, частичные входы усредняются. Повторная загрузка файла не создаёт дублей. Если формат не распознан, журнал покажет найденные колонки.
- Светлая и тёмная тема (по настройкам системы), вёрстка под телефон.

## Как запустить

Откройте `index.html` в браузере, и всё работает.

Сайт публикуется на Cloudflare автоматически: Cloudflare подключён к репозиторию и после каждого merge в `main` сам собирает (`npm run build`) и выкладывает сайт. GitHub Actions для этого не нужны. Настройки деплоя лежат в `wrangler.jsonc`, в сайт попадает только папка `dist/`.

Подключить один раз: Cloudflare → **Workers & Pages** → **Create** → **Import a repository** → `trades-tracker`, команда сборки `npm run build`, команда деплоя `npx wrangler deploy`.

## Как вносятся изменения

1. Изменения приходят pull request'ом в `main`.
2. Workflow **Check** сам прогоняет `npm test`: открывает сайт в браузере без интерфейса и проверяет основные сценарии (форма, расчёты, календарь, импорт, удаление, вёрстка на телефоне).
3. Cloudflare собирает для pull request'а превью-версию сайта, ссылка появляется в проверках PR.
4. Когда всё зелёное, остаётся нажать **Merge pull request**, и сайт обновится сам.

Запустить проверки локально: `npm ci && npx playwright install chromium && npm test`.

## Где хранятся данные

Сделки хранятся в `localStorage` вашего браузера, скриншоты — в IndexedDB. Своего сервера у приложения нет.
Без синхронизации данные привязаны к браузеру и устройству. Регулярно делайте резервную копию через **Импорт / экспорт → Скачать JSON** (со скриншотами), а на другом устройстве загружайте её через **Заменить журнал**.

## Синхронизация между устройствами

Журнал можно хранить в приватном [GitHub Gist](https://gist.github.com/) вашего аккаунта:

1. Создайте токен на <https://github.com/settings/personal-access-tokens/new>. В правах аккаунта (Account permissions) добавьте **Gists: Read and write**, другие права не нужны.
2. В приложении нажмите **Синхронизация**, вставьте токен и нажмите **Подключить**. Приложение найдёт gist с файлом `trades-tracker.json` или создаст новый.
3. На втором устройстве вставьте тот же токен.

После каждого изменения журнал синхронизируется сам (и при возвращении на вкладку). Если правки сделаны на двух устройствах, они объединяются: для каждой сделки побеждает последняя правка, удаление побеждает правки, сделанные до него.

Ограничения:
- Скриншоты не синхронизируются, их можно перенести JSON-файлом.
- Токен хранится в браузере, поэтому давайте ему доступ только к Gists и задайте срок действия.
- В предпросмотре на claude.ai синхронизация не работает (он не пускает запросы к GitHub). Используйте опубликованный сайт или открытый локально `index.html`.

При первом запуске показываются примерные сделки. Они удаляются кнопкой «Удалить примеры и начать» или автоматически, когда вы добавите первую свою сделку.

## Telegram-бот

Бот работает в том же Cloudflare Worker, что и сайт (`worker/index.js`), и пишет сделки в gist журнала. Журнал подтягивает их при синхронизации.

Настройка, один раз:

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя → скопируйте токен.
2. Cloudflare → **Workers & Pages** → `trades-tracker` → **Settings** → **Variables and Secrets** → добавьте секреты (тип **Secret**):
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `GITHUB_TOKEN` — GitHub-токен с правом Gists: Read and write (можно тот же, что в синхронизации журнала);
   - `TIMEZONE` — по желанию, например `Europe/Moscow` (по умолчанию так и есть).
3. Откройте `https://<адрес сайта>/tg/setup`. Страница напишет «Бот подключён».
4. Напишите боту `/start`. Он пришлёт ваш Telegram ID. Добавьте его секретом `TELEGRAM_OWNER_ID`. Пока владелец не задан, бот никому ничего не записывает, а чужим отвечает, что он личный.

Команды:

```
long BTC 64000 0.1 стоп 63000 тейк 66000 #FOMO заметка
шорт ETH 2600 1.5 sl 2650 tp 2500
закрыть BTC 65000          — закрыть позицию целиком
закрыть BTC 65000 0.05     — закрыть часть
/open  /today  /stats  /undo
```

Синхронизация в журнале должна быть подключена: бот ищет gist с файлом `trades-tracker.json`.

## Формат CSV

Первая строка содержит заголовки. Обязательные поля: `symbol`, `side` (`long`/`short`), `openedAt`, `entry`, `qty`.

```
id,symbol,market,side,openedAt,closedAt,entry,exit,qty,fees,stop,target,setup,notes
,BTCUSDT,Крипто,long,2026-10-01T10:00,2026-10-02T15:30,61250,62480,0.15,7.4,60600,63000,Пробой уровня,
```

Даты записываются в формате `ГГГГ-ММ-ДДTчч:мм`. Если `exit` пустой, сделка считается открытой.
